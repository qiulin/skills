# 独立设计与交叉验证（Independent Design）

一个大脑设计一个方案，盲区就是一个人的盲区。派多个互不可见的子代理独立设计同一个问题，再用交叉验证收割收益：独立得出的共识给信心，分歧暴露真正的决策点，只被一人发现的盲点给补强。隔离是价值来源——子代理一旦看到别人的方案就会锚定，收敛的置信度随之作废。

## 何时使用

- 重要方案：架构选型、数据模型、迁移策略，错了代价高
- 用户说"派子代理独立设计""交叉验证""多方案对比"
- 单方案评审后仍不放心，想要真正独立的多视角

## 操作步骤

**阶段一：出题（原会话）**

1. **固化任务契约**。背景（项目路径、现状、硬约束）、目标与范围、统一输出契约——每个子代理按相同章节交付：方案概述、关键设计、关键决策及理由、风险与盲点自报、改动面清单。章节统一，交叉比较才有基准。
2. **隔离派发**。每个子代理的 prompt 自足且互斥：只含背景与任务，不提其他子代理的存在。背景只陈述事实，原会话自己的倾向一个字都不给。

**阶段二：独立设计（子代理，并行）**

3. **并行派发 2-3 个子代理**。2 个是最低配置（可交叉），3 个可多数参照。收集各自按契约返回的设计。

**阶段三：交叉验证（原会话）**

4. **建比较矩阵**。行 = 设计维度（数据结构、接口、流程、错误处理……），列 = 各方案，逐格对齐。
5. **三类收割**：
   - 收敛点——多个方案独立得出的相同结论：高置信，直接进最终方案，标注"独立收敛"；
   - 分歧点——结论冲突处：不投票，逐点审双方论据、回溯到目标与约束裁决；仍裁不了的，把对方方案发回对应子代理做一轮定向批判（每点限一轮），或明确标为开放问题留给验收方；
   - 独有点——只被一个方案发现的风险或优化：先验证真伪，真的并入，伪的记录排除理由。
6. **综合最终方案**。收敛点做骨架、裁决结果定分叉、有效独有点做补强，按 design-only 七部分产出单一方案；每个部件标注来源（收敛/裁决/独有），追溯链完整。
7. **盲区终检**。两问：各子代理自报的盲点，最终方案都覆盖了吗？对照输出契约逐维度扫一遍，所有方案都没提到的维度是什么——这是最难的问题，因为没有人替你想过；有则补进方案的开放问题。

完成标准：比较矩阵 + 收敛/分歧/独有三类收割记录 + 单一最终方案（部件带来源标注）+ 盲区终检记录。

## 标志性追问

- "子代理互相看到对方方案了吗？"（看到了，收敛置信度作废）
- "这个分歧点，双方论据回溯到目标与约束后哪边更硬？"
- "这个独有发现验证过真伪吗？"
- "所有方案都没提的维度是什么？"

## 失败模式

- 假独立：派发 prompt 里泄露倾向（"我倾向用队列"）。背景只给事实，收敛置信度靠隔离换来，泄露一次全部作废。
- 交叉变背书：先有偏好再走流程，只挑自己想要的。矩阵先于裁决，每个分歧点双方论据都要过一遍。
- 多数暴政：收敛只说明"想到一块了"，不说明"对"。采纳前回溯约束；特立独行的那个方案要认真验证，而不是直接淘汰。
- 二选一硬凑：两个方案都不满意时，加派一个小成本第三轮定向补设计，不在烂苹果里挑大的。

## 与相关 skill 的衔接

- 输出契约与 design-only 的七部分方案对齐；最终方案可直接交给 handoff-implement 生成实现 prompt；
- 分歧点需要反方攻击时，用 adversarial-review 的手法组织定向批判。

## 示例

- Before：用户："导出数据流设计，派两个子代理独立做，交叉验证。"
- After：契约统一（背景：订单表 8000 万行、现有同步导出超时；章节固定）；两个子代理隔离并行。矩阵对齐：A、B 都选游标分页流式写（收敛，采纳）；分叉在任务化——A 主张同步流式（实现简单），B 主张异步任务加进度查询，审论据：产品硬约束"可离开页面"，裁决取 B 的任务化、用 A 的游标做内部实现；独有点——B 发现任务表需要 TTL 清理，验证为真，并入。终检：双方自报盲点中的"并发任务上限"已覆盖；契约维度"权限"两个方案都没展开 → 列入开放问题。最终方案每个部件标注（收敛/裁决/独有）。
