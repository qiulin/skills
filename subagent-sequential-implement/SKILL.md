# 依次派子代理实现（Subagent Sequential Implement）

大方案整包交给一个会话，上下文越长质量越漂，错误越积越深。切成有序阶段，一个子代理负责一段，段与段之间设验收门——错误被拦在它诞生的阶段，回退只损失一段，不损失全部。

## 何时使用

- 方案较大（多模块、多步骤），单会话实现的后半程质量没有把握
- 用户说"派子代理依次实现""分阶段做""一步一步来"
- design-only / design-doc 的分步实施计划已就绪，需要逐段落地
- 需要每段之间有验收门和回退还原点

## 操作步骤

**阶段〇：切分（原会话）**

1. **从方案到阶段清单**。以分步实施计划为底稿，切成 2-5 个有序阶段，每段写清四件事：范围（做什么/明确不做什么）、可验收产出（完成判据）、依赖（依赖前序哪些产出）、规模（一个子代理会话能保质完成的量）。
2. **垂直切优先**。按功能垂直切（每段从数据到接口交付可运行的增量），阶段结束时系统可运行、可验收；技术底座必须先行时才水平切，且水平段尽量短、尽快接上垂直段——中间态无法验收的水平大段是风险后置。

**阶段循环（每个阶段重复）**

3. **生成阶段 prompt**。自足，包含：背景（项目路径、设计文档路径）＋整体设计中与本阶段相关的要点＋**前序阶段已完成事实**（产出清单＋还原点 commit，写明禁止重做前序工作、禁止改动本阶段范围外的文件）＋本阶段验收标准＋输出要求（执行汇总）。
4. **派一个子代理实现**。一次只派一个；前一阶段未过验收门，不派后一阶段。
5. **阶段验收（门）**。逐条标准一手取证（自己跑测试、读 diff、运行行为——汇报不是证据），另加一条**全局一致性检查**：改动符合设计文档的全局意图，而不是只为了通过本阶段标准、破坏前序或整体。
6. **还原点**。验收通过后提交一个 commit（消息注明阶段号），作为回退锚点；会话未获提交授权时，以文件清单记录代替。未通过 → 整改 prompt 只含不合格项，重派本阶段，直至通过才前进。

**收尾**

7. **终验**。全部阶段完成后按方案整体成功标准做全量回归：全量测试、关键路径实走一遍、改动范围与方案核对；附全部阶段的执行汇总与验收记录。终验通过后可按需触发 adversarial-review 或 rethink 做质量复查。

完成标准：每个阶段有 prompt、执行汇总、验收记录、还原点；终验附全量证据链。

## 标志性追问

- "这个阶段结束时，系统可运行、可验收吗？"
- "子代理会重做或破坏前序阶段的产出吗？prompt 里圈住了吗？"
- "这个改动符合全局设计意图，还是只为过本阶段标准？"
- "此刻失败回退，损失多少？"（一段，不是全部）

## 失败模式

- 水平大切：先做完所有数据层再做逻辑层，中间态无法验收，风险全部后置。垂直切，让每段都交付可运行增量。
- 阶段间漂移：每个子代理只顾本阶段标准，全局意图逐段走样。阶段 prompt 引用设计文档，验收门必含全局一致性检查。
- 并行上头：看到阶段就想一起派。有依赖必须串行；确认无共享文件、无依赖的片段才可并行，且合并后的验收仍归原会话。
- 门形同虚设：扫一眼执行汇总就放行。门的意义是拦错，取证标准与严格验收相同。

## 与相关 skill 的衔接

- 阶段清单的底稿：design-only / design-doc 的分步实施计划；
- 阶段 prompt 方法：handoff-implement 阶段一；阶段验收：其阶段四；执行汇总：execution-summary；
- 最终交付：按 handoff-implement 的验收对照表归档，回填 design-doc 状态为"已实现"。

## 示例

- Before："按方案把导出功能做了，拆几个子代理依次来。"
- After：切 3 阶段——①导出核心（CSV 生成＋转义＋测试，垂直可运行）②任务化包装（异步任务＋进度表＋查询接口）③收尾（TTL 清理任务＋文档更新）。每阶段 prompt 引用 `docs/design/2026-09-10-export.md` 与前序还原点。阶段①验收发现转义未覆盖引号场景 → 整改 prompt 只含该项 → 重验通过 → 还原点 `f1e2d3`。三阶段全过后终验：全量测试、10 万行计时 26s、改动范围核对，附 3 份执行汇总与验收记录。
