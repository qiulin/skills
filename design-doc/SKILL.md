# 方案落文档（Design Doc）

方案只存在于对话里，等于没有方案。落盘的目标是六个月后还能被找到、看懂、考古：目录按类型分、文件名带日期、状态放文档头、索引不缺席。文档的价值密度在决策理由——"为什么这么做"必须随档，"要做什么"只是壳。

## 何时使用

- 用户说"方案落到文档""写成设计文档""落盘""归档"
- design-only 产出方案后需要持久化
- handoff-implement 需要一份可引用的设计依据文件
- 项目还没有 docs 结构，需要一次定好

## 操作步骤

1. **勘察现有文档约定**。查仓库里 `docs/`、`doc/`、`design/`、根目录散落的 `.md`：已有目录结构和命名风格优先沿用——一个仓库只允许一套文档组织，禁止另起炉灶。仓库里没有文档结构时才引入下面的默认结构。
2. **设计目录**。默认最小结构：

   ```
   docs/
   ├── README.md                          # 索引：一张表管全部方案
   └── design/
       └── 2026-09-10-order-cancel.md     # 日期前缀 + 英文 kebab 主题
   ```

   三条设计原则：
   - **按文档类型/生命周期分目录，不按业务模块分**。类型（design、adr、runbook……）少而稳定，业务模块会漂移；需要 adr 时加 `docs/adr/`，用不上就不加；
   - **状态放文档头，不放文件名**。状态会变（草案→已评审→已实现→已废弃），文件名跟着状态改会断掉所有引用；
   - **方案文档是档案**：只改状态和追加关联，不删除。被否掉的方案也要留——考古"当初为什么不这么做"和"当初为什么这么做"同样值钱。

3. **写正文**。头部元数据表 + 方案七部分（现状与问题、目标设计、关键决策及理由、分步实施计划、风险与对策、测试策略、明确不做的事），结构对齐 design-only：

   ```markdown
   # <标题>

   | 状态 | 日期 | 关联 |
   |---|---|---|
   | 草案 | 2026-09-10 | issue #123 / 替代了 2026-08-01-xxx.md |

   <七部分正文>
   ```

4. **更新索引**。`docs/README.md` 的方案表加一行：日期、标题、状态、一句话说明、文件链接。没有索引文件就创建——新方案不进索引等于藏在雪地里。
5. **交付核对**。`git status` 确认只动了 docs/ 下的文件；向用户说明状态维护纪律：实现完成后把状态改为"已实现"并补 PR 链接，废弃时改"已废弃"并指向替代方案。

完成标准：方案文件落在约定目录、命名合规、头部有状态元数据、正文七部分齐全、索引表已更新、除 docs/ 外零改动。

## 标志性追问

- "仓库里已有文档惯例吗？我沿用了还是另起炉灶？"
- "六个月后想找这份方案，靠什么路径找到？"（目录名、文件名、索引，三重可发现性）
- "被否掉的方案留档了吗？理由还在吗？"
- "这份文档实现后，谁在什么时候改状态？"

## 失败模式

- 按业务模块建目录：`docs/order/`、`docs/user/`……业务模块越多目录越乱，而文档类型就那几种。
- 状态写进文件名：`-draft.md`、`-final-v2.md`——状态一变就要改名，所有链接失效。
- 索引失修：文档加了、索引没更，三周后没人记得 docs 里有什么。
- 方案文档写成需求清单：只有"要做什么"，没有"为什么"和"否掉了什么"。实现阶段的每次偏离都会因为理由缺失而显得合理。
- 过度分类：三层目录、五种文档类型。目录深一层，可发现性降一截。

## 与相关 skill 的衔接

- design-only 的方案是本 skill 的输入（对话 → 文档）；
- handoff-implement 生成 prompt 时可直接引用落盘文档路径作为实现依据；
- 实现验收通过后，回到本 skill 更新状态为"已实现"并关联 PR，形成闭环。

## 示例

- Before："这个迁移方案不错，记到文档里吧。"→ 随手建了个 `迁移方案.md` 丢在根目录。
- After：勘察发现仓库无 docs 结构 → 创建 `docs/design/2026-09-10-order-sharding.md`，头部状态"草案"、关联 issue #88；正文含分片键选型记录（选 user_id，否掉 order_id，理由：80% 查询带 user_id）；`docs/README.md` 索引加一行；`git status` 确认只新增两个文档文件。
