# 机制缺口排查（Mechanism Gap）

问题暴露的地方几乎从不是问题产生的地方。崩溃点加个判断、坏数据手工修一条、文档里写句"请注意"——这些都是处理实例；机制补齐处理的是类别：让下一同类问题在更早的层被拦住，或发生的瞬间被发现。

## 何时使用

- bug、线上事故、数据错误需要定修复方案
- 同类问题反复出现，修了一处又冒一处
- 用户说"从机制上解决""别打补丁""根治一下"
- 评审他人的修复方案，判断是补丁还是机制

## 操作步骤

1. **还原逃逸路径**。沿因果链从现象回溯到产生点：这个问题途经哪些本可拦截的层（类型检查、入口校验、静态检查、测试、评审、监控告警），逐层记录为什么没拦住——没有检查？有检查但没覆盖这种情况？覆盖了但被绕过？逃逸路径就是缺口的地图。
2. **判定问题类别**。这是个孤立个案，还是一类问题的实例？判据：历史上修过同类问题吗？同样成因换个地方还会发生吗？成因是系统性的（缺约束、缺校验、靠自觉）还是偶发的（一次手滑、一次外部故障）？力度要匹配类别——偶发个案不配上重机制。
3. **识别机制缺口**。对逃逸路径上的每一层问：加什么守卫能让这类问题在这层被拦住或立刻暴露？机制层清单（按拦截时点从早到晚）：
   - **数据结构/类型约束**——让非法状态不可表示（必填字段不可空、枚举收窄取值）；
   - **边界校验**——入口处拒绝非法输入，不让脏数据进系统；
   - **静态检查/lint**——模式化的错误自动发现，不靠人眼；
   - **测试**——该类别的回归用例，修过的不再犯；
   - **CI 门禁**——不合格不放行，把"记得跑"变成"必须过"；
   - **运行时断言/告警**——拦不住就立刻知道，缩短暴露时间；
   - **流程自动化**——把"靠人记得"变成"不可能忘"（自动化检查、模板、钩子）。
4. **给出补齐方案与验收**。推荐**最早可拦截的层**（越早修复成本越低），机制方案的验收标准只有一句话："下一个同类问题会在哪一层被拦住？"——能指认具体的层和具体守卫才算机制补齐，说不出来就还是补丁。
5. **打补丁的正确姿势**。需要止血时补丁照打，但要做三件事：标注为临时；同一条修复里开出机制任务并挂跟踪；补丁注释里写明对应的机制任务号。止血与补机制并行，禁止"补丁打完问题关闭"。

完成标准：输出包含逃逸路径（每层为何失守）、类别判定（个案/一类）、机制补齐方案（指认层 + 具体守卫 + "下个同类问题在哪被拦"的验收标准）；如有临时补丁，必有伴生机制任务。

## 标志性追问

- "这个问题是怎么穿过所有防线的？每层为什么没拦住？"
- "同样成因，换个地方还会发生吗？"
- "这个修复在处理实例，还是在消灭类别？"
- "下一个同类问题会在哪一层被拦住？"
- "这个方案依赖人记得什么吗？"（靠记性的都是补丁）

## 失败模式

- 就地打补丁：只在崩溃点加判断、只修坏掉的那条数据。暴露点不是产生点，同类问题只是换了地方排队。
- 机制过敏：偶发个案就上重型监控、大流程。先做类别判定再定力度，机制的维护成本也是成本。
- 止血变终点：紧急补丁打完即宣告解决。没跟出机制任务的问题会再次回来，且带着利息。
- 万物皆机制：把所有问题都上升成机制建设，当下没人修。先修当下、再补机制，两件事并行而非互斥。
- 靠自觉的机制：文档写"请注意 X"、群里喊一声不是机制——人会忘；能自动执行的才叫守卫。

## 与相关 skill 的衔接

- rethink 的"根因还是现象"、critical-thinking 的归因分析为逃逸路径回溯提供方法；
- 修复方案落地走 handoff-implement / sequential-implement，机制守卫（lint 规则、测试、门禁）作为验收标准的一部分冻结进 prompt。

## 示例

- Before：线上 NPE，在用到处加 `if (x != null)`，关闭问题。
- After：逃逸路径回溯——该字段从构造入口就允许为空，途经入口校验（无）、单测（未覆盖缺字段场景）、监控（报错才知）；判定为一类问题（所有必填字段同构风险）。机制补齐：类型上必填不可空（构造强制）、API 边界校验拒绝缺失（返回 400）、补该类回归测试。验收："下一个缺字段的请求在 API 边界即被拦。"当次 `if` 保留为纵深防御，注释标注对应机制任务 #142。
